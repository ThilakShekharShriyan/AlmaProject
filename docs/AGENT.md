# Coding agent usage

Cursor was the harness: edits, search, the shell, and the browser. Skills told the agent how to write the code. The daisyUI skill supplied the component API, so the screens are `navbar`, `hero`, `card`, `fieldset`, `input`, `file-input`, `btn`, `alert`, and `badge` on the `cream` theme in `globals.css`, not a custom stylesheet. The Next.js and TypeScript rules kept data loading in server components and `use client` on the form, sign-in, and Reach out button. The Karpathy guidelines skill kept each change small: no extra services and no speculative abstraction. Supabase MCP applied the schema and confirmed the attorney user. Vercel MCP created the project, set env, attached `leads.thilakshekharshriyan.com`, and connected GitHub. The browser MCP checked the form, the signed-in gate, and the lead list. GitHub Actions runs `npm ci`, `tsc --noEmit`, and `next build`. A push to `main` deploys.

I delegated that first draft, from the lead row and resume upload through the React screen. I kept the decisions. Supabase owns auth, Postgres, and the `resumes` bucket. Resend owns the two emails. The FastAPI split came out because this state machine did not need four processes. The prospect form stays public. The attorney list stays behind the `access_token` cookie. Log out renders only on `/leads`. A signed-in attorney cannot submit.

One bad result got past a stored lead. `onSubmit` called `event.currentTarget.reset()` after `await fetch`. React clears `currentTarget` on the first await, so the page threw `Cannot read properties of null (reading 'reset')` after a 200. I caught it by submitting the form and reading the stack. `apps/web/app/apply/apply-form.tsx` now keeps the form element before the request and resets that reference.
